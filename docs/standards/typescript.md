# TypeScript and Node

Standards for every TypeScript package in this repository: the engine, the hub, the Angular client, the Lambda handlers, and the tooling around them. The client follows these where Angular's own conventions do not say otherwise; "The client" below says where they do.

## Rules

### Versions and dependencies

1. **Latest, preferring LTS where it exists.** Node is the current LTS line, pinned by major in `.node-version` at the repository root; `fnm`, CI, the bundler's target and the Lambda runtime identifier (`nodejs<major>.x`, in Terraform) all follow that one number. Libraries are kept at their latest release; a library with an LTS line is kept on that line. Falling behind is a defect to fix, not a state to maintain. Dependabot opens the pull requests (`.github/dependabot.yml`); a major that cannot be taken yet is listed under "Held back" at the end of this document, with the reason and what releases it, and is ignored in `.github/dependabot.yml` by the same pull request.
2. **Exact pins, committed lock file.** `package.json` names exact versions, never ranges, and `package-lock.json` is committed. CI installs with `npm ci`, so what runs there is what ran on the laptop.
3. **Install scripts are approved by name.** npm withholds packages' install scripts until they are listed under `allowScripts` in the root `package.json`. A new one is approved with `npm install-scripts approve <package>`, in the pull request that introduces the dependency, and the pull request description says what the script does.
4. **One source of truth for functions and routes.** `manifest.json` at the repository root lists every Lambda with its handler, memory, timeout and routes. The bundler and Terraform read it; nothing declares a function or route anywhere else.

### Language and modules

5. **ES modules only.** Every package is `"type": "module"`. Imports of local files carry the `.js` extension, as Node's ESM resolution requires. The base settings live in `tsconfig.base.json`; a package overrides only what it must, and says why in a comment.
6. **Strict everything.** `strict`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noPropertyAccessFromIndexSignature` and `verbatimModuleSyntax` are on and stay on, in `tsconfig.base.json`. A type error is fixed at its cause. `any` is a last resort and carries a comment. The non-null assertion `!` is not used: a value that may be absent is narrowed, or its absence fails with a message, as `must(value, what)` does, one function in the engine (`packages/engine/src/must.ts`, exported from `@heat/engine`, the package every other package imports, rule 7) and used by every package's source and tests, and as `callerId` does in the hub's resolvers (lint rule `no-non-null-assertion`, rule 16). In source, `must` names the invariant the code relies on, a Map entry just written or an index a loop keeps in range, so that the invariant failing fails there with a message rather than later as a TypeError. A property of an index signature is read with brackets, `env["HEAT_VERSION"]`, which is what the flag enforces, so that a dynamic key looks dynamic.
7. **Shared code is a package, not a Lambda.** Logic the client and the backend both need, above all the engine, is a workspace package that both import. A Lambda never invokes another Lambda to run shared logic.

### Testing

8. **Vitest, in every package, run by `npm test` at the root.** Unit tests need nothing installed. Integration tests start their own containers through Testcontainers, so they need Docker and nothing else, on a laptop and on CI alike (decision 0009). A package's `tsconfig.json` covers its tests and its `vitest.config.ts` as well as its source, so `npm run typecheck` and the typed lint (rule 16) see them; a package that emits, the engine, builds from `tsconfig.build.json`, which narrows that to `src`.
9. **Handlers are tested as functions.** A Lambda handler is exercised by calling it with a synthesized event of the exact shape AWS sends, never through a mocked SDK inside the code under test. What a handler's middleware does is tested the same way, by calling the handler, not by calling the library in its place: from the review of PR-209, where a test flushed the metrics itself and so no test showed `logMetrics` doing it.

### The hub

10. **Apollo Server, Pothos code-first, scope-auth for authorization.** Field-level access is declared as scopes on fields and types; a field the caller may not read resolves to null with an error on that field, so such fields are declared nullable.
11. **The printed schema is committed, and the client's code is generated from it.** `npm run schema:print` writes `packages/hub/schema.graphql` from the Pothos builder; CI fails if the committed file is stale. Every pull request that changes the API therefore shows the change as a schema diff. `npm run codegen` then generates the client's operations and types from that file with GraphQL Code Generator's client preset (`codegen.mjs` at the root), into `packages/client/src/app/graphql/generated/`, committed too and checked current by CI the same way, so the client never reads a running hub to build and the same pull request shows the client's types changing beside the schema (`docs/standards/angular.md`, rule 5).

### Bundling

12. **One ESM file per function.** `scripts/bundle.mjs` bundles each function from the manifest with esbuild into `dist/<name>/`, targeting the Node major in `.node-version`, dependencies included, Powertools among them. Terraform zips that directory and passes it to the function with its hash, so a code change is a change in the plan (decision 0017). Logging goes through the Powertools logger as JSON lines, tracing through its tracer and metrics through its metrics as embedded metric format lines in the log, all at one version, configured by the environment variables Terraform sets on the function. `@middy/core` wraps a handler with the three Powertools middlewares, `injectLambdaContext`, `captureLambdaHandler` and `logMetrics`, with the function's own handler innermost, and only those: what middy's other middlewares do, Apollo's plugins and the integration's own option already do for the hub. Its early timeout is off, `timeoutEarlyInMillis: 0`, so that a function never answers with work still pending (decision 0040).

### The client

13. **Angular, latest major, every `@angular/*` package on one exact version.** `packages/client` is an Angular application generated by the Angular CLI: standalone components, zoneless, the router, Vitest through `@angular/build:unit-test` with jsdom, no server-side rendering. Angular's packages move together, with `ng update` on a branch of their own, because the update runs the migrations between majors; Dependabot therefore ignores `@angular/*` majors, and `angular-eslint`'s, whose major tracks Angular's, and takes the minors and patches with everything else. Angular states the TypeScript versions it accepts (22 accepts `>=6.0 <6.1`), so the repository's one TypeScript pin follows Angular's window. How the client itself is written, its components, where its data lives, its templates and the scene's boundary, is `docs/standards/angular.md`, which applies beside this document.
14. **One tsconfig base, the bundler's overrides.** `packages/client/tsconfig.json` extends `tsconfig.base.json`, as rule 5 says, and overrides what the Angular build needs: `module: preserve`, `moduleResolution: bundler`, the DOM libraries, no declarations, and Angular's own flags, each with its reason in the file. Rule 6's flags stay on. Local imports in the client are extensionless, Angular's convention, because the bundler resolves them and Node never runs them; rule 5's `.js` extension is for the packages Node runs.
15. **The dev server and the build.** `npm start --workspace @heat/client` serves the client at `http://localhost:4200` with live reload, and `proxy.conf.mjs` sends `/graphql`, `/previous/graphql` and `/config.json` to the branch's stack, so the local page is that stack's client (decision 0018; `docs/process/development.md`, rule 5; added by Issue-46, not Issue-39 as first written). `npm run build --workspace @heat/client` is the production build, into `packages/client/dist/client/browser`, under Angular's default budgets but one: the initial bundle warns at 750 kB rather than 500 kB, raised by Issue-156 when Apollo Client, Apollo Angular and `graphql` took the initial bundle from 419 kB to 604 kB, while the error budget stays Angular's 1 MB; "Build and test" runs it on every pull request, and its output is what a stack's bucket serves (Issue-39). `npm test` runs the client's tests once (`ng test --watch=false`) beside every other package's. The art the client draws, `art/heroes`, `art/monsters`, `art/props`, `art/weapons`, `art/effects`, `art/facilities`, `art/ground` and `art/icons`, is copied into the git-ignored `packages/client/generated/art` before every serve, build and test (`packages/client/scripts/copy-art.mjs`) and served at `/art`, because Angular takes assets only from inside its workspace root and the art has one home, at the repository root with its provenance (Issue-81). The favicon is one of that art, `art/icons/favicon.png`, so the client has no `public` folder; the build also puts it at the site root as `/favicon.png`, which `scripts/publish-client.sh` publishes with the page's short cache rather than the year-long one of everything else, because browsers ask for a favicon at a fixed address (Issue-89).

### Lint

16. **Lint is the floor.** `npm run lint` at the root runs ESLint over every workspace from one flat config, `eslint.config.mjs`, and "Build and test" runs it beside the typecheck, so a finding fails the pull request. A change is not ready for review until it lints clean, and a convention a lint rule can express is expressed as one, in the config, not as prose here; model-driven review, the review skill on a pull request (`docs/runbooks/review-change.md`) and the checkup skill at a pause (`docs/runbooks/checkup.md`), starts where lint stops (decision 0033). The rule sets are the published ones, at their strictest tier: `@eslint/js` recommended for plain JavaScript; typescript-eslint's `strictTypeChecked` and `stylisticTypeChecked`, with type information from each package's `tsconfig.json`, for every TypeScript file; angular-eslint's `all` tier for the client's components and for its templates, in files and inline alike, which holds its accessibility rules; `@graphql-eslint`'s `all` tier for the committed schema; and `no-console` on the hub's source, whose logging has one path (`docs/standards/graphql.md`, rule 16). Imports in every JavaScript and TypeScript file are grouped and sorted by `perfectionist/sort-imports`, Node built-ins, packages, `@heat/*`, local files, a blank line between groups, and the names inside their braces by `perfectionist/sort-named-imports`, with one declaration per module, types inline (`no-duplicate-imports`), so a new import has one place to go and the fixer puts it there (Issue-183). An `all` tier is taken whole, with the rules that contradict a convention of ours named off beside their reason, as the typescript-eslint tiers are. A rule is turned off, or its option changed, only with a one-line reason in the config, and the reason is about the rule, never about the code: `restrict-template-expressions` allows a number, `non-nullable-type-assertion-style` is off because it writes the `!` that rule 6 forbids, `no-unused-vars` takes the `_` prefix as deliberate, `no-extraneous-class` allows a decorated class in the client because the framework instantiates a component from its decorator and one whose whole content is its template has no members, and the client's and the schema's own exceptions stand in the config with theirs (`docs/standards/angular.md`, rules 3 and 13; `docs/standards/graphql.md`, rules 1 and 6). A rule the code cannot meet yet is held back for those files only, by file pattern at the end of the config, naming the issue that removes the hold-back, and is listed under "Held back" in the standards document whose convention it expresses. The strict tier is not semver-stable: a typescript-eslint minor may add a rule, and the Dependabot pull request that brings it goes red until the finding is fixed on that branch, which is the floor doing its job.

### Libraries

17. **A known library over our own.** For a common problem, a popular, well-known, current library is preferred over a solution of our own, and is adopted whole where it fits, as Angular, Apollo, Pothos, Powertools and PixiJS are: exact-pinned (rule 2), tracked by Dependabot (rule 1), and named here so that each idiom has one spelling. The weighting is the owner's of 2026-11-03: the application is built as an enterprise system would be, and a common problem takes the library used there, for what it shows and teaches, not only when the code outgrows it. Writing our own is the exception, taken when no current library does the job or when what the code needs is smaller than the library's cost, and the code says so in a comment. The validation library is zod, spelled `import * as z from "zod/mini"` in every package, because the chained API adds 429 kB to the client's first page where this one adds 14 kB (decision 0039). The data layer is ElectroDB, behind the repository (decision 0041; `docs/standards/graphql.md`, rule 17). The utility library is es-toolkit (decision 0036), a dependency of the engine, the hub and the client: where it has a named function for what the code does, `range`, `clamp`, `sortBy`, `uniq`, `sum`, `sumBy`, `upperFirst`, `groupBy`, `keyBy`, `mapValues`, that function is used, in source and tests alike; the standard library is used where it reads as plainly on its own, `flatMap`, `find`, a spread, `Object.fromEntries` over pairs, a numeric comparator on numbers. Not replaced by it: `must` (rule 6), which returns the narrowed value where `invariant` only asserts; a `Map` or `Set` that is a cache, a registry or a membership test; and a loop that re-reads between attempts, which `retry` does not express. Weighed against a library and kept, each for its reason: the engine's seeded random, because replay would then depend on a library's stream staying bit-identical across releases (and es-toolkit's `random` is `Math.random`); DataLoader, until a field resolves a list over N parents, which build order step 3 brings; the Powertools idempotency utility, which raises on an in-flight duplicate where the hub answers the work as it is (`docs/standards/graphql.md`, rule 7); a JWT library, because the authorizer has already verified the token (rule 12 of that document); the Terraform registry modules, because the project's own module library carries the guardrail reasoning per argument (`docs/standards/terraform.md`); and the plan-comment and release actions, because the scripts redact the account id and check the saved plan.

### Closed sets

18. **A list that enumerates a closed union is checked against it.** An exported list of a union's members, `UNIT_TYPES`, `MATERIALS`, `FACILITY_KINDS`, `MONSTER_TYPES`, `RESOURCE_TYPES`, `STAGE_ENDINGS`, `ADVENTURE_OUTCOMES`, is the one declaration: the list is `as const` and the union is `(typeof LIST)[number]`, so a member added to one is added to the other. Where the union is declared elsewhere, `StageKind` from `Stage`, the list `satisfies` it and a typed assignment beside it fails on a member the list lacks. A list annotated `readonly T[]` is not checked: a member added to the union alone compiles and is dropped from whatever the list feeds, the API's enums among them (graphql.md, rule 4). A closed set spelled in more than one place inside a package has one exported list, and every other place reads it, an unexported inline list included: `HERO_STATUSES` in the hub's `db/statuses.ts` feeds the entity, the union and the API's enum. From the reviews of PR-192 (Issue-155) and PR-212 (Issue-200).

### Shared test helpers

19. **A helper shared by a package's test files is written once**, in one module under the package's `test/` that every test file imports, never copied into each; `packages/hub/test/refusal.ts` holds `refusal` and `BAD_USER_INPUT`. This covers a block of set-up repeated across test files, named or not. From the review of PR-192, which found five copies, and of PR-214.

### Types over a library's

20. **A type that corrects a library's says the value's true shape, and any cast the library's signature needs stands at the call.** A type bent so that a value passes reads as true everywhere it is used; the cast at the call says once where the library's signature is wrong. From the review of PR-214, on `RawPage.LastEvaluatedKey`.

## Held back

Majors not taken, each with the reason and what releases it. A lint rule not yet met is listed in the standards document whose convention it expresses (rule 16): none, in this document or in `docs/standards/graphql.md`, since Issue-155. Checked 2026-11-02.

- **graphql 17.** Apollo Server 5 declares graphql `^16.11.0` as its peer dependency; Pothos accepts 16 or 17. Released when Apollo Server accepts 17.
- **Node 26.** Node 24 is the LTS line and 26 is Current. Released when 26 enters LTS, as rule 1 says.
- **TypeScript 7.** The latest tag; 6.0.3 is pinned. Angular 22 accepts `>=6.0 <6.1` (rule 13), so 7 waits for an Angular release that accepts it, then a trial on a branch showing that Pothos, Vitest and the Angular tooling compile and test under it.

## Why

Latest with LTS preferred is the owner's standing policy for every tool and library, stated 2026-10-14: a project that exists to show current practice should run on current versions, and the cost of staying current in small steps is far below the cost of a large jump later. Exact pins and the lock file make the laptop and CI identical, which decision 0009 depends on. The install-script approval is npm's own control since 11.19; recording approvals in the repository turns a per-machine prompt into a reviewed decision. The manifest exists because the bundler and Terraform would otherwise each hold a copy of the same routes and drift. Committing the printed schema is how a code-first project keeps schema-first's one real advantage, a reviewable contract.

Lint is the first layer of the review programme agreed on 2026-10-23 (Issues 144 to 147): the one layer that is deterministic and free, so that the model-driven layers spend nothing on what a linter knows. The strictest published tier was the owner's call, for a codebase meant to show current practice, and its cost was measured first: 525 findings on `main` that day against 163 for the recommended tier, most of them non-null assertions in tests, which is why rule 6 changed from "a last resort with a comment" to "not used" in the same pull request. Three pull requests pay that cost, one per area, because one would not have been reviewable line by line. The client's and the schema's rule sets moved from the recommended tiers to the `all` tiers on 2026-10-24 (Issue-145), when the owner weighted accepted practice over the code as it was: the `all` tiers cost 35 findings, 25 of them fixed by the fixer, and nine rules named off, each for a convention this project holds against the rule rather than for the code's convenience.

The client's rules were added on 2026-10-17 with the first Angular code (Issue-45). Angular releases its packages as one set and names the TypeScript versions it accepts, so the packages are pinned to one version and moved as one, and the TypeScript pin moved from 5.9.3 to 6.0.3 for Angular 22; the engine and the hub compiled and tested under 6.0.3 unchanged.

Rule 17 comes from the review of PR-153 (Issue-149) and was adopted by Issue-154 on 2026-11-02: the code wrote by hand what a utility library names, a range in sixteen places, a clamp both ways round, one-key sort comparators, `[...new Set(xs)]`, each correct and each a second read to see what it means. The project has two readers, a person and a coding agent, and a named function serves both: lodash's vocabulary, which es-toolkit keeps, is read without learning, and a named call is harder to get wrong than three nested `Math` calls. Under rules 1 and 2 and es-toolkit's per-function modules the dependency costs little, and the one real cost, two spellings for one idiom, is what the rubric in the rule removes. What was weighed, lodash, remeda, tiny-invariant and the idioms as they were, is decision 0036.
