# Angular

Standards for `packages/client`, the Angular application, beside `docs/standards/typescript.md`, which applies to it in full: its TypeScript rules, and its rules 13 to 15 for the client's versions, its tsconfig, the dev server and the build. This document says how the client itself is written: what a component is and holds, where the data lives, where PixiJS stops and Angular begins, what a template may say, what is tested how, and what a stylesheet is. Written on 2026-10-24 (Issue-145) from the code on `main` and from decisions 0024, 0028 and 0030, with accepted practice stated as the rule and the code's distance from it under "Held back". A convention a lint rule can express is in `eslint.config.mjs`, not here (typescript.md, rule 16); the rules below say which rule holds each where one does.

## Rules

### The shape

1. **Standalone, zoneless, signals.** Every component is standalone (lint `prefer-standalone`), under Angular's default change detection, which is OnPush since Angular 22 and which no component opts out of (lint `prefer-on-push-component-change-detection`); the application is zoneless (`app.config.ts`). State is a `signal`, derived state a `computed`, and a side effect an `effect`, which reads what it follows first and does its work in `untracked` where that work must not be followed. An observable the framework hands over, the router's `paramMap`, becomes a signal at once with `toSignal`; nothing in a component subscribes by hand or holds a `Subscription`. A component's input is `input()` or `input.required()`, its output `output()`, its view query `viewChild` (lint `prefer-signals`, `prefer-output-emitter-ref`, `no-uncalled-signals`).
2. **Dependencies by `inject()`, at the top of the class.** A component or service takes its dependencies as fields initialized with `inject()`, before any other field, because fields initialize in order and a `computed` written above an `inject` could not read it (lint `prefer-inject`, `inject-at-top`). A root service is `@Service()` (lint `prefer-service-decorator`); an `@Injectable()` with no `providedIn` is one a component provides in its `providers` and lives exactly as long as that component: `CampState` by the camp, `Play` by the adventure page. A dependency a test must replace is an `InjectionToken` with a factory, so the test provides a fake and the code never branches on where it runs: the scene factories, the frame loop, the reload, the session's `UserManager`, the layout sizes.
3. **Names.** A class is named for what it shows or does, with no `Component`, `Directive` or `Service` suffix, as Angular's style guide has it since v20: `Camp`, `HallPanel`, `Game` (lint `component-class-suffix` and `directive-class-suffix` are off for that reason). Its files are `<name>.ts`, `<name>.html`, `<name>.css` and `<name>.spec.ts` beside each other, in a directory per feature: `camp/`, `camp/panels/`, `camp/scene/`, `adventure/`, `adventure/battle/`. A selector is `heat-` and kebab-case for a component, `heat` and camelCase for a directive (lint `component-selector`, `directive-selector`). The keys of a decorator are in one order (lint `sort-keys-in-type-decorator`).

### Where the data lives

4. **One client of the hub.** `Hub` (`hub.ts`) is the one place a request leaves the page: the link chain Apollo sends every operation through, which sets the stack's GraphQL path on this origin, the signed-in player's token and the client's version header, reads the `outdated` flag off every response, errors included, and sends an operation whose context names the previous deploy to `/previous` in front of the path (decisions 0024 and 0030). `app.config.ts` provides Apollo with that chain and with the schema's union and interface members (`graphql/generated/possible-types.ts`), so the cache matches a fragment on `Error` or on a result union. Nothing else calls `fetch` or builds a link.
5. **`Game` is the player's state and every action.** `Game` (`game.ts`) holds the player as the hub answered, watched through Apollo: the `Me` query, started after `joinGame` once signed in and read again after every mutation, with `player`, `loading` and `error` derived from its result; the camp on screen; and the derived views the pages read (`camp`, `heroesHere`, `livingHere`, `adventure`, `recruits`). It is the one caller of Apollo. Every operation is a `.graphql` file under `graphql/`, one definition per file with the fragments it imports, generated by GraphQL Code Generator's client preset into typed documents and types (`graphql/generated/`, from `npm run codegen` at the root, committed and checked current by CI; typescript.md, rule 11), and linted against the committed schema (graphql.md, rule 1), so a document the hub would refuse fails before it is pushed. Every view type is derived from its fragment's generated type, with the engine's closed sets read back at the boundary (rule 6); no view type and no query string is written by hand. Every mutation is a method on `Game`, which sends one input object, reads the result union by `__typename`, and answers what the success wrapped or throws the hub's refusal as a `Refusal` named by its result type (`HallFull`, `InsufficientResources`, `AdventureOpen`; graphql.md, rule 6), and reads the player again either way, since a refusal means the view was stale. What Apollo throws, an entry of the response's `errors` array, malformed input, a caller not signed in, or the hub not reached, is an `ApiError` with its code (`apiError` in `hub.ts`): a defect or an outage, never a refusal. A component calls `Game` and never Apollo.
6. **A refusal becomes words where it is shown.** The hub answers a refusal type; the component that shows the refusal maps the type's name to the player's words in a `REFUSALS` table beside the component, and shows a type it does not know as the hub put it. A wire value the client does not know is not a crash: `Game` reads the schema's enum values back into the engine's at its boundary (`engineValues` in `game.ts`), and a value this client's engine lacks, sent by a newer deploy (decision 0030), passes through in the engine's spelling, so a new unit type or material lets an older tab load and shows as content it does not know. A refusal is shown in place, beside the control that was refused, with `role="alert"`, never as a page-wide error. The in-flight state of an action belongs to the same place: the component that calls a mutation keeps a `pending` signal beside its refusal, set around the call, and disables its control on it; there is no page-wide busy flag, because a recruit under way in the hall is no reason to refuse a retirement on a card. A rule the client can check before asking, a price against a balance or a hall at its cap, is the engine's rule (`recruitCost`, `buildRefusal`), computed in `Game` and shown as the disabled control's reason; the hub checks it again (graphql.md, rule 9).
7. **What the page knows about its stack** comes from `config.json`, read once before the application starts (`Config`, the initializer in `app.config.ts`), checked against one zod schema that is also its type (`StackConfigSchema`, decision 0039), and the session is built from it (`Session`, decision 0024). A file that fails the check is recorded, not thrown, so the page renders and says what is wrong. Nothing in the code branches on where it runs: not on the hostname, not on `localhost`.

### Pages, panels and plain modules

8. **A page is a route, a panel is a child route.** The camp and the adventure are pages at their paths, and what the content area shows is a child route under the camp (`app.routes.ts`; game.md, "The page"), so the address says where the player is and back returns to the last panel. A panel is its own component under `camp/panels/`, shares `panel.css`, and reads what it shows from `Game` and `CampState`. A route a signed-out player may not open carries the `signedIn` guard, which keeps the path for sign-in to return to (decision 0024 as amended). A page not needed at first load is `loadComponent`, so its code and what it imports are a chunk of their own (`/adventure`).
9. **Arithmetic and words are plain modules.** Where things stand and how big they are (`page-layout.ts`, `battle-layout.ts`, `scene/layout.ts`, `scene/wander.ts`), what the events say (`field.ts`), and the player's words for the content (`job-words.ts`) are exported functions with no Angular and no renderer in them, tested as functions. A component holds what it shows and what the player did; a computation of more than a line is a `computed` or a function in such a module.
10. **A number or a word the player sees is named.** A limit, a speed, a size or a label is a named constant: in the engine where the rule is the engine's (`MAX_PARTY`), in the module whose arithmetic it is (`HEADER_PX`, `MIN_VIEW_WIDTH`), or in the component, with a comment saying what it is and where it comes from; the template reaches it through a `protected readonly` field (`maxParty`, `speeds`) and never holds a literal of its own.

### The scene

11. **PixiJS draws, Angular owns the page** (decision 0028). A scene is a plain module, `camp/scene/camp-scene.ts` and `adventure/battle/battle-scene.ts`, exporting one `create…Scene(host, …, callbacks)` that answers a handle with its `set…`, `feed` and `frame` methods and `destroy`. It imports PixiJS and the engine's content, never Angular, `Game` or `Hub`; it is handed what to draw and reports clicks through its callbacks, and the component decides what a click means. It is reached only through its `InjectionToken` factory, which loads it with a dynamic `import()`, so PixiJS is a chunk of its own and a test provides a scene that draws nothing. Pixel art is drawn nearest-neighbour at a whole number of device pixels per art pixel; the arithmetic that decides the number is a plain module (rule 9).

### Templates

12. **Templates and styles in their own files.** `templateUrl` and `styleUrl`, never inline (lint `component-max-inline-declarations` at zero); a test's route target that renders nothing is the shared `Blank` component under `testing/`. Styles are the component's own file, or `panel.css` shared by the panels; the global `styles.css` holds the page's base and the tokens of rule 17, and nothing of one component. A size the page computes is bound, `[style.height.px]`; a literal `style` attribute is not written (lint `no-inline-styles`).
13. **The template reads; it does not compute.** Control flow is `@if`, `@for` with `track`, `@switch` with `@default` (lint `prefer-control-flow`, `use-track-by-function`, `require-switch-default`); a value is a signal read, a field, or a pipe (`date`, `lowercase`; lint `prefer-built-in-pipes`); a string is a template literal (lint `prefer-template-literal`); anything more is a `computed` or a function of rule 9. An image is `ngSrc` through `NgOptimizedImage`, with its width and height (lint `prefer-ngsrc`). Attributes follow one order (lint `attributes-order`, which fixes it). A template is in English and carries no `i18n` marks, because the game has one language (lint `i18n` is off for that reason); a signal is read by calling it (lint `no-call-expression` is off for that reason); and the count of a template's `@if` and `@for` blocks is not limited (lint `cyclomatic-complexity` is off), because the logic such a limit guards against lives in `computed` signals by rule 9.
14. **Accessibility is lint's rules and these.** angular-eslint's accessibility rules apply through the `all` tier (typescript.md, rule 16). Beyond them: every button has `type="button"` (lint `button-has-type`) and says what it does; a panel is a region whose heading its `aria-labelledby` names (`panel-title`); a group of controls has `role="group"` with a label; a refusal or a failure the player must see has `role="alert"`; a toggle says its state with `aria-pressed`; a control that cannot be used now is `disabled` with its reason shown beside it, not hidden.

### Tests

15. **A component is tested through the router with fakes for its services.** `TestBed` with `provideRouter(routes)` and `RouterTestingHarness`, the real component tree, and `Game`, `Session` and the scene and frame tokens provided as fakes written in the spec, which record what was called, so a test exercises what the player sees and does and not the service behind it. `Game` itself is tested through Apollo Angular's `ApolloTestingModule`, whose controller answers each operation the way the hub would, on the application's own cache (`APOLLO_TESTING_CACHE` with the generated `possibleTypes`), and `Hub`'s link chain through Angular's `HttpTestingController`, so the headers and the path of a request are read as they leave. Where jsdom differs from a browser, the code checks the capability, not the environment, and says so in a comment: `typeof window.matchMedia !== 'function'`, `'devicePixelContentBoxSize' in entry`.
16. **A plain module is tested as functions,** in its own spec with no `TestBed`. The property the client's modules protect, that a run and its replay show the same, is the engine's test, not the client's.

### Styles

17. **Styles are plain CSS, and what more than one component needs is a token.** A stylesheet is plain CSS, with native nesting where it reads better, and no preprocessor without a decision record (decision 0037). A color or a size that appears in more than one component is a custom property on `:root` in `styles.css`, named for what it is and not for its value, which the components read with `var()`: the palette (`--night`, `--ink`, `--bar`, `--parchment`, `--gold`, `--light`, `--rust`, `--ember`), the spacing scale (`--space-xs` to `--space-2xl`), the type sizes beside the base (`--text-sm`, `--text-lg`), the border widths (`--border-thin`, `--border`, `--border-thick`) and the page's regions (`--header-height`, `--menu-rail-width`, `--menu-labelled-width`, `--menu-row-height`, and the panel's `--panel-min-width`, `--panel-share` and `--panel-max-width`, composed into `--panel-width`). A color of the palette and a step of a scale are declared with their set even where one component reads them, so that the next use finds its token and not a literal. A component declares no custom property that another component also needs, and a value that belongs to no set and is used once stays a literal where it is used. A size the layout arithmetic needs is never written twice: the regions are in `rem`, and `page-layout.ts` reads them from the tokens at runtime through `readLayoutSizes` and the `LAYOUT_SIZES` token, resolved to CSS pixels at the player's root font size, so the page follows the player's settings (best-practices.md, rule 10). A breakpoint is a literal, because a media query cannot read a custom property.

## Held back

Nothing, since Issue-156 (2026-11-02) generated the client and replaced `fetch` with Apollo Angular.

## Why

The shape rules are Angular's own current recommendations, standalone components, zoneless change detection, signals, `inject()`, `@Service()`, the v20 style guide's names, and the `all` tier of angular-eslint is their enforcement. A developer who knows Angular should recognize the client at a glance, which is the owner's weighting of 2026-10-24: accepted practice over the code as it was. The nine findings the `all` tier raised that the fixer could not fix were four fields out of order, two switches without a default, two images without `ngSrc` and one method call a pipe replaces, fixed in the same pull request.

Where the data lives follows from decisions 0024 and 0030: the token, the version header and the `outdated` flag are handled in one place or they are handled inconsistently, and a component that called the hub would carry a copy of that handling. The generated client is decision 0012's shape, reached on 2026-11-02 (Issue-156): the operations are validated against the committed schema by lint and by generation, so the defect PR-192 shipped, a fragment spread on a union with no such member, found only at the stack URL, cannot recur; fragment masking is off because one service reads every result; the views derive from the generated types so that a change of the schema is a change of the client's types in the same diff; and the pending state per control replaced a page-wide `busy` flag that disabled unrelated controls, because a mutation's in-flight state is per call in Apollo as in Angular's own guidance. The refusal-to-words table beside the component keeps the hub's refusal types as the contract names them and the words where a reader of the panel expects them (Issue-82, Issue-115; the types since Issue-155). A wire value passing through rather than throwing is the client's half of decision 0030: a tab older than the hub is normal between a deploy and the reload the `outdated` flag triggers, and the review of PR-192 found `load()` failing whole on one new enum value.

The scene boundary is decision 0028's reason: the rules never run in PixiJS, so they are tested without a renderer, and PixiJS is loaded only where it is drawn, so the first page stays small. The plain modules exist for the same reason at a smaller scale; the layout arithmetic of Issues 89, 95 and 99 was argued over in numbers, and numbers in a function with a spec are what settled it.

The template rules are Issue-149's readability convention made general: a literal in a template has no name and no reason beside it, a named constant has both. The lint rules that are off are off for a convention, not for the code: signals are read by calling them, the game has one language, and the complexity a template could hide is already forbidden by rule 9.

The styles rule is decision 0037, plain CSS with a token layer: custom properties are the token mechanism in both camps, Angular defaults to CSS and recommends nothing, and Angular Material, the one place Sass would be required, emits its theme as custom properties that plain CSS reads. The arithmetic reads the tokens because the pixel constants that copied them were true only at the default font size, which the review of PR-189 found.
