# Angular

Standards for `packages/client`, the Angular application, beside `docs/standards/typescript.md`, which applies to it in full. This document says how the client itself is written and built: its versions, tsconfig, dev server and build, what a component is and holds, where the data lives, where PixiJS stops and Angular begins, what a template may say, what is tested how, and what a stylesheet is (Issue-145; decisions 0024, 0028 and 0030). Accepted practice is stated as the rule. A convention a lint rule can express is in `eslint.config.mjs`, not here (typescript.md, rule 16); the rules below name the lint rule that holds each. The detail of a rule, what this document holds back and why its rules are as they are, is `docs/standards/angular-detail.md`, which nothing loads; its opening says when each section is read (decision 0060).

## Rules

### The shape

1. **Standalone, zoneless, signals.** Every component is standalone (lint `prefer-standalone`), under Angular's default change detection, OnPush since Angular 22, which no component opts out of (lint `prefer-on-push-component-change-detection`); the application is zoneless (`app.config.ts`). State is a `signal`, derived state a `computed`, and a side effect an `effect`, which reads what it follows first and does its work in `untracked` where that work must not be followed. State that starts again from what it follows, as a job's party pick does when the address names another job, is a `linkedSignal`, never an `effect` that writes a signal (Issue-440). An observable the framework hands over, the router's `paramMap`, becomes a signal at once with `toSignal`; nothing in a component subscribes by hand or holds a `Subscription`. A component's input is `input()` or `input.required()`, its output `output()`, its view query `viewChild` (lint `prefer-signals`, `prefer-output-emitter-ref`, `no-uncalled-signals`).
2. **Dependencies by `inject()`, at the top of the class,** before any other field, because fields initialize in order and a `computed` written above an `inject` could not read it (lint `prefer-inject`, `inject-at-top`). A root service is `@Service()` (lint `prefer-service-decorator`); an `@Injectable()` with no `providedIn` is provided by a component and lives exactly as long as it: `CampState` by the camp, `Play` by each battle page, whose shared regions (`BattleView`) and controls (`Playback`) inject the page's. A dependency a test must replace is an `InjectionToken` with a factory, so the test provides a fake and the code never branches on where it runs: the scene factories, the frame loop, the reload, the session's `UserManager`, the layout sizes.
3. **Names.** A class is named for what it shows or does, with no `Component`, `Directive` or `Service` suffix, as Angular's style guide has it since v20: `Camp`, `HallPanel`, `Game`. Its files are `<name>.ts`, `<name>.html`, `<name>.css` and `<name>.spec.ts` beside each other, in a directory per feature: `camp/`, `camp/panels/`, `camp/scene/`, `adventure/`, `adventure/battle/`. Selectors and the order of a decorator's keys are lint's (the companion's "Rule 3").

### Where the data lives

4. **One client of the hub.** `Hub` (`hub.ts`) is the one place a request reaches the hub: the link chain Apollo sends every operation through, which sets the stack's GraphQL path, the player's token and the client's version header, reads the `outdated` flag off every response, a refusal with HTTP 400 included, and sends an operation whose context names the previous deploy to `/previous` (decisions 0024 and 0030). Nothing else builds a link or sends a request to the hub. The page's own static files, `config.json` and the art's JSON, are fetched where they are read, by `Config` (rule 7) and `fetchJson` (`static-json.ts`), and checked at that fetch against a zod schema that is their type, never cast with `as`, so a file the build copied wrong fails with its name at the fetch; a sprite set's sheet, which PixiJS loads itself, is checked the same way where it is loaded (`loadSpriteSet` in `sprite-sheet.ts`, with `checkJson`; Issue-268). The companion's "Rule 4" says what `app.config.ts` gives Apollo.
5. **`Game` is the player's state and every action.** `Game` (`game.ts`) holds the player as the hub answered, watched through Apollo's `Me` query, read again after every mutation, with `player`, `loading` and `error` derived from it, the camp on screen and the derived views the pages read. It is the one caller of Apollo, and a component calls `Game`, never Apollo. Every operation is a `.graphql` file under `graphql/`, one definition per file, generated into typed documents (typescript.md, rule 11) and linted against the committed schema (graphql.md, rule 1); every view type derives from its fragment's generated type, the engine's closed sets read back at the boundary (rule 6), and none is written by hand. Every mutation is a method on `Game` that sends one input object, reads the result union by `__typename`, answers what the success wrapped or throws the refusal as a `Refusal` named by its type (graphql.md, rule 6), and reads the player again either way, since a refusal means the view was stale. What Apollo throws is an `ApiError` with its code (`apiError` in `hub.ts`): a defect or an outage, never a refusal.
6. **A refusal becomes words where it is shown.** The component that shows a refusal maps the type's name to the player's words in a `REFUSALS` table beside it, typed by the closed set it is keyed by, so a member added to the set is a compile error at the table: `RecruitRefusal` through `RefusalOf` in `hub.ts`, a stage's endings by `StageEnding`; where a newer deploy can send a member this client lacks, the fallback is written once, at the lookup (`refusalWords`, `endingWords`; Issue-268). A wire value the client does not know is not a crash: `Game` reads the schema's enum values back into the engine's (`engineValues` in `game.ts`), and an unknown one passes through in the engine's spelling (decision 0030). A refusal is shown in place, beside the control that was refused, with `role="alert"`. The component that calls a mutation keeps a `pending` signal beside its refusal and disables its control on it; there is no page-wide busy flag. A rule the client can check before asking, a price against a balance or a hall at its cap, is the engine's rule (`recruitCost`, `buildRefusal`), computed in `Game` and shown as the disabled control's reason; the hub checks it again (graphql.md, rule 9).
7. **What the page knows about its stack** comes from `config.json`, read once before the application starts (`Config`, the initializer in `app.config.ts`), checked against one zod schema that is also its type (`StackConfigSchema`, decision 0039), and the session is built from it (`Session`, decision 0024). A file that fails the check is recorded, not thrown, so the page renders and says what is wrong. Nothing in the code branches on where it runs: not on the hostname, not on `localhost`.

### Pages, panels and plain modules

8. **A page is a route, a panel is a child route.** The camp and the adventure are pages at their paths, and what the content area shows is a child route under the camp (`app.routes.ts`; game.md, "The page"), so the address says where the player is and back returns to the last panel. A panel is its own component under `camp/panels/`, shares `panel.css`, and reads what it shows from `Game` and `CampState`. A route a signed-out player may not open carries the `signedIn` guard, which keeps the path for sign-in to return to (decision 0024 as amended). A page not needed at first load is `loadComponent`, so its code is a chunk of its own (`/adventure`, `/replays/<id>`).
9. **Arithmetic and words are plain modules.** Where things stand and how big they are (`page-layout.ts`, `battle-layout.ts`, `scene/layout.ts`, `scene/wander.ts`), what the events say (`field.ts`), and the player's words for the content (`job-words.ts`, `result-words.ts`, `replay-words.ts`) are exported functions with no Angular and no renderer in them, tested as functions. A component holds what it shows and what the player did; a computation of more than a line is a `computed` or a function in such a module.
10. **A number or a word the player sees is named.** A limit, a speed, a size or a label is a named constant: in the engine where the rule is the engine's (`MAX_PARTY`), in the module whose arithmetic it is (`STAGE_WIDTH`, `MIN_VIEW_WIDTH`), or in the component, with a comment saying what it is and where it comes from; the template reaches it through a `protected readonly` field (`maxParty`, `speeds`) and never holds a literal of its own.

### The scene

11. **PixiJS draws, Angular owns the page** (decision 0028). A scene is a plain module, `camp/scene/camp-scene.ts` and `adventure/battle/battle-scene.ts`, exporting one `create…Scene(host, …, callbacks)` that answers a handle with its `set…`, `feed` and `frame` methods and `destroy`. It imports PixiJS and the engine's content, never Angular, `Game` or `Hub`; it is handed what to draw and reports clicks through its callbacks, and the component decides what a click means. It is reached only through its `InjectionToken` factory, which loads it with a dynamic `import()`, so PixiJS is a chunk of its own and a test provides a scene that draws nothing. Pixel art is drawn nearest-neighbour at a whole number of device pixels per art pixel; the arithmetic that decides the number is a plain module (rule 9).

### Templates

12. **Templates and styles in their own files.** `templateUrl` and `styleUrl`, never inline (lint `component-max-inline-declarations` at zero); a test's route target that renders nothing is the shared `Blank` component under `testing/`. Styles are the component's own file, or `panel.css` shared by the panels, or `battle-panel.css` shared by the battle pages and their controls; the global `styles.css` holds the page's base and the tokens of rule 17, the global `primitives.css` the shared `.button` and `.frame`, and nothing of one component. A size the page computes is bound, `[style.height.px]`; a literal `style` attribute is not written (lint `no-inline-styles`).
13. **The template reads; it does not compute.** A value is a signal read, a field, or a built-in pipe; anything more is a `computed` or a function of rule 9. Control flow, `track`, `@default`, template literals, `ngSrc` and the order of attributes are lint's, and so are the rules named off, `i18n`, `no-call-expression` and `cyclomatic-complexity`, each for its reason: the companion's "Rule 13".
14. **Accessibility is lint's rules and these.** angular-eslint's accessibility rules apply through the `all` tier (typescript.md, rule 16). Beyond them: every button has `type="button"` (lint `button-has-type`) and says what it does; a panel is a region whose heading its `aria-labelledby` names (`panel-title`); a group of controls has `role="group"` with a label; a refusal or a failure the player must see has `role="alert"`; what arrives on a page with no action of the player's and is news to them, a drop counted up or an unlock told, is in a live region, `role="status"`, that is in the page before the news and empty until then, since one that arrives already holding its words is not reliably spoken (the review of PR-361, Issue-352); a toggle says its state with `aria-pressed`; a control that cannot be used now is `disabled` with its reason shown beside it, not hidden.

### Tests

15. **A component is tested through Angular Testing Library, by what the player sees and does, with fakes for its services** (decision 0044). `render`, `screen`, `within` and `waitFor` come from `@testing-library/angular/zoneless` (lint `no-restricted-imports`). A page is reached through the router by `renderAt(url, routes, providers)` from `testing/render-at.ts`, with the real component tree. Things are found by role and name, then label, then visible text, scoped with `within`; no `data-testid` and no CSS selector (lint `testing-library/no-container`, `no-node-access`), and a control a query cannot name is a defect of rule 14, not of the spec. A list a spec reads is found by its name, never by its place (`listItems` and `itemHolding` in `testing/page.ts`). A click goes through the test's one `userEvent.setup()`, which `renderAt` answers as `user`. An element's whole text is matched whole, not with `toHaveTextContent`'s substring. What a page does after an action is waited for with `findBy…` or `waitFor`. `Game`, `Session` and the scene and frame tokens are fakes that record what was called; one spec's fake is in that spec, a shared one under `testing/` (typescript.md, rule 19). What has nothing to render keeps `TestBed`: the companion's "Rule 15", with where jsdom differs from a browser.
16. **A plain module is tested as functions,** in its own spec with no `TestBed`. The property the client's modules protect, that a run and its replay show the same, is the engine's test, not the client's.

### Styles

17. **Styles are plain CSS, and what more than one component needs is a token.** A stylesheet is plain CSS, with native nesting where it reads better, and no preprocessor without a decision record (decision 0037). A colour or a size that appears in more than one component is a custom property on `:root` in `styles.css`, named for what it is and not for its value, read with `var()`. Colour is two layers (decision 0061): the palette, each colour named for what it is, and the roles over it, named for what they do, such as `--surface-panel`; a component, a script through `colourToken` and a scene through `readColourRole`, reads only a role, only `styles.css` reads the palette, and elsewhere no colour or `px` length is a literal, even once, which stylelint holds in the stylesheets (`stylelint.config.mjs`) and lint, for a colour, in the client's TypeScript, `ground-sets.ts` excepted. What the art build knows it writes into `generated/frames.css`, never copied by hand. A role nothing reads leaves `styles.css` in the change that stops the last read. A colour of the palette and a step of a scale are declared with their set even where one component reads them; a value that belongs to no set and is used once stays a literal where it is used, and a component declares no custom property another also needs. A size the layout arithmetic needs is never written twice: the regions are in `rem`, and `page-layout.ts` reads them from the tokens at runtime through `readLayoutSizes` and `LAYOUT_SIZES`, so the page follows the player's settings (best-practices.md, rule 10). A breakpoint is a literal, because a media query cannot read a custom property. The tokens there are, and the primitives, are the companion's "Rule 17".

### The page in a browser

18. **A running stack's page is tested by Playwright; everything else stays in the unit tests** (decision 0045). `packages/client/e2e/` asks one question, whether a real browser gets from the stack's hostname to a drawn camp and back: signing in and out, the scene's canvas, a broken page or missing art, and one path through the panels. A panel's words, a refusal, an edge of the rules or a layout is a spec's (rules 15 and 16), and what the hub answers is `scripts/e2e.mjs`'s. It finds things by role and label (lint `playwright/no-raw-locators`) and watches for a broken page from before its first navigation. A trace holds a password and tokens and never leaves the runner unencrypted (`scripts/seal-browser-trace.sh`), because the repository is public.

### The previous deploy

19. **The cleanest wire shape comes first, and a break of the previous route is said, not designed around.** The submit is the one operation the client also sends to `/previous/graphql` (decision 0030). A field added to its selection while the previous deploy of some environment lacks it is refused there with HTTP 400, and an adventure open across that deploy can be neither settled nor discarded until the deploy after. That is accepted: the pull request that adds the field says which environments break once and when, for the owner to accept, as decision 0038 did; a second read kept to spare the bridge is chosen only where the owner judges the break too costly (Issue-355). A new unlock is still read from `me.unlocks`, because what the player holds is the player's (decision 0059).

### Versions and the build

20. **Angular, latest major, every `@angular/*` package on one exact version.** `packages/client` is an Angular CLI application: standalone components, zoneless, the router, Vitest through `@angular/build:unit-test` with jsdom, no server-side rendering. Angular's packages move together, by `ng update` on a branch of their own, because the update runs the migrations between majors; Dependabot ignores the `@angular/*` and `angular-eslint` majors and takes their minors and patches. The repository's one TypeScript pin follows the TypeScript versions Angular accepts (Issue-45; was typescript.md, rule 13).
21. **One tsconfig base, the bundler's overrides.** `packages/client/tsconfig.json` extends `tsconfig.base.json` (typescript.md, rule 5) and overrides only what the Angular build needs, each with its reason in the file; typescript.md's rule 6 flags stay on. Local imports in the client and in its browser test are extensionless, Angular's convention, because the bundler and Playwright's loader resolve them and Node never runs them (was typescript.md, rule 14; the companion's "Rule 21").
22. **The dev server and the build.** `npm start --workspace @heat/client` serves the client at `http://localhost:4200`, and `proxy.conf.mjs` sends `/graphql`, `/previous/graphql` and `/config.json` to the branch's stack, so the local page is that stack's client (decision 0018; `docs/process/development.md`, rule 5). `npm run build --workspace @heat/client` is the production build, under Angular's default budgets but the initial bundle's warning, 750 kB (Issue-156); "Build and test" runs it, and its output is what a stack's bucket serves (Issue-39). The art is written into the git-ignored `packages/client/generated/art` before every serve, build and test and served at `/art`, because Angular takes assets only from inside its workspace and the art has one home, `art/` with its provenance (Issue-81): sprite sets and a font's glyphs packed into a sheet, effects and ground copied, and pictures, icons, frames and portraits under names that carry their hash, with the index the page reads, so that art made again reaches a browser that kept the old. What each is written as is the companion's "Rule 22" (was typescript.md, rule 15).
