# Angular: the detail

The detail behind `docs/standards/angular.md`: what its rules need when their kind of work is done, not at a session's start, what it holds back and why its rules are as they are. Its rules are that document's, by their numbers there; each section here is named for the rule it serves (decision 0060, as amended by Issue-428).

Nothing loads this file. It is read by section when the work names it (`docs/process/sessions.md`, rule 18), and whole by the review skill and the checkup: "Rules 2 to 6" when a service, the hub's client, `Game` or a refusal's words change; "Rule 13" when a lint rule on templates goes red or is weighed; "Rule 15" when a spec is written for what has nothing to render, or jsdom differs from a browser; "Rule 17" when a token or a primitive is added; "Rules 18 and 19" when the browser test or the submit's selection changes; "Rules 20 to 22" when Angular is updated, the client's tsconfig changes, or the art build or what it writes for the page changes; "Held back" when an angular-eslint rule is held back for some files (`typescript.md`, rule 16); "Why" when a rule's reason is in doubt.

## Rules 2 to 6: services, the hub's client, `Game` and refusals

Rule 2: `Play` is provided by each battle page, the adventure's and a replay's.

Rule 3: lint `component-class-suffix` and `directive-class-suffix` are off because of the names rule 3 gives. A selector is `heat-` and kebab-case for a component, `heat` and camelCase for a directive (lint `component-selector`, `directive-selector`). The keys of a decorator are in one order (lint `sort-keys-in-type-decorator`).

Rule 4: `Hub`'s chain reads the `outdated` flag off errors as well as answers. `app.config.ts` provides Apollo with that chain and with the schema's union and interface members (`graphql/generated/possible-types.ts`), so the cache matches a fragment on `Error` or on a result union. The art's JSON is the JSON beside its images; what the build wrote beside a sprite set's atlas is checked against its schema where the sheet is loaded.

Rule 5: `Me` is started after `joinGame` once signed in. The derived views are `camp`, `heroesHere`, `livingHere`, `adventure` and `recruits`. An operation file holds its one definition with the fragments it imports, generated by GraphQL Code Generator's client preset into `graphql/generated/` by `npm run codegen` at the root, committed and checked current by CI, and linted so that a document the hub would refuse fails before it is pushed. No query string is written by hand. A refusal's type names are those of the hub, `HallFull`, `InsufficientResources`, `AdventureOpen`. What Apollo throws is an entry of the response's `errors` array (graphql.md, rule 6) or the hub not reached.

Rule 6: the hub answers a refusal type, and a type the component does not know is shown as the hub put it. A refusal is never shown as a page-wide error. The `pending` signal is set around the call; a recruit under way in the hall is no reason to refuse a retirement on a card, which is why there is no page-wide busy flag. A value an older client lacks, a new unit type or material, lets an older tab load and shows as content it does not know.

## Rule 13: the template's lint rules

Control flow is `@if`, `@for` with `track`, `@switch` with `@default` (lint `prefer-control-flow`, `use-track-by-function`, `require-switch-default`); a pipe is a built-in one, `date`, `lowercase` (lint `prefer-built-in-pipes`); a string is a template literal (lint `prefer-template-literal`). An image is `ngSrc` through `NgOptimizedImage`, with its width and height (lint `prefer-ngsrc`). Attributes follow one order (lint `attributes-order`, which fixes it). A template is in English and carries no `i18n` marks, because the game has one language (lint `i18n` is off for that reason); a signal is read by calling it (lint `no-call-expression` is off for that reason); and the count of a template's `@if` and `@for` blocks is not limited (lint `cyclomatic-complexity` is off), because the logic such a limit guards against lives in `computed` signals by rule 9.

## Rule 15: what has nothing to render, and jsdom

The main entry point of `@testing-library/angular` is refused because it imports the deprecated `RouterTestingModule`. What no route shows, the header, or a page a test must stay on after it navigates, Home, is `render`ed itself. A list is found by the heading its `aria-labelledby` names or its `aria-label`, and one a query cannot tell apart is given a label. Keystrokes go through the same `userEvent.setup()` instance (lint `testing-library/prefer-user-event`, `prefer-user-event-setup`). An assertion on an element is a `jest-dom` matcher, loaded by `src/test-setup.ts`; where a spec states an element's whole text it matches the whole text, with `getByText` or an anchored pattern, since `toHaveTextContent` with a plain string matches a substring. `settle` from `renderAt` is for what a test does outside the page, a frame of the run. The fakes are there so that a test exercises what the player sees and does and not the service behind it.

What has nothing to render keeps `TestBed` (lint refuses it in every other spec): `Game` itself is tested through Apollo Angular's `ApolloTestingModule`, whose controller answers each operation the way the hub would, on the application's own cache (`APOLLO_TESTING_CACHE` with the generated `possibleTypes`), and `Hub`'s link chain through Angular's `HttpTestingController`, so the headers and the path of a request are read as they leave, and `Session`, `Updates`, the `signedIn` guard and the application's initializers are injected the same way. Where jsdom differs from a browser, the code checks the capability, not the environment, and says so in a comment: `typeof window.matchMedia !== 'function'`, `'devicePixelContentBoxSize' in entry`.

## Rule 17: the tokens and the primitives

The tokens on `:root` are the colour roles, the spacing scale (`--space-xs` to `--space-2xl`), the type sizes beside the base (`--text-sm`, `--text-lg`), the border widths (`--border-thin`, `--border`, `--border-thick`), the art's pixels (`--frame-outline`, `--frame-edge`, `--frame-corner`, `--button-press`, `--pixel`) and the page's regions (`--header-height`, `--menu-rail-width`, `--menu-labelled-width`, `--menu-row-height`, and the panel's `--panel-min-width`, `--panel-share` and `--panel-max-width`, composed into `--panel-width`). What the art build writes into `generated/frames.css` is each frame's `--frame-<name>-*` and `--portrait`, a build constant at its scale. The layout sizes are resolved to CSS pixels at the player's root font size. The primitives other than the buttons and the frame of rule 12 are components in `src/app/primitives/`, shown by `/gallery` with them. A colour of the palette and a step of a scale are declared with their set so that the next use finds its token, not a literal.

## Rules 18 and 19: the browser test and the previous deploy

Rule 18: a test added to `e2e/` for a panel's words, a refusal, an edge of the rules or a layout is slow and tells the reader less than a spec.

Rule 19: a field added to the submit's selection counts `ResultFields` too, and the refusal at validation comes before any resolver. The pull request says which environments break, from where `main` and `release` stand. A result reads its fields where they belong, on the submit's own result; a second read that only the current route answers is the alternative the owner may choose for one change.

## Rule 20: Angular's version

Dependabot ignores `angular-eslint`'s majors because its major tracks Angular's; minors and patches come with everything else. Angular 22 accepts TypeScript `>=6.0 <6.1`. Rules 20 to 22 were `docs/standards/typescript.md`, rules 13 to 15, until Issue-428 moved them to the client's loader.

## Rule 21: the client's tsconfig

`packages/client/tsconfig.json` overrides `module: preserve`, `moduleResolution: bundler`, the DOM libraries, no declarations, and Angular's own flags. `docs/standards/typescript.md`'s rule 5 `.js` extension is for the packages Node runs.

## Rule 22: what the build writes for the page

The production build writes `packages/client/dist/client/browser`. The initial bundle warns at 750 kB rather than Angular's 500 kB, raised for the GraphQL client (Issue-156), while the error budget stays Angular's 1 MB. `npm test` runs the client's tests once (`ng test --watch=false`) beside every other package's. The proxy is Issue-46's.

The art is written by `packages/client/scripts/copy-art.mjs`. A sprite set, under `art/heroes`, `art/monsters`, `art/props` and `art/weapons`, and a font's glyphs under `art/fonts`, cut from its atlas (`docs/process/assets.md`, rule 37), is packed into one sheet, an image named for its pixels and the atlas that names it, `sheet.json`, which is published to be read again within a minute, and its frames and provenance are not published (`pack-art.mjs`; `docs/process/assets.md`, rule 4; Issue-205). `art/effects` and `art/ground` are copied as they are, and a facility's pictures under names that carry a hash of the file, with `pictures.json` beside them, which gives each picture's name and the row it stands on and is published with the same short lifetime, so the row a scene reads is always the row of the picture it draws.

An icon is copied the same way, under a name that carries its file's hash, with `art/icons/pictures.json` naming each, which the page reads before it starts and the battle scene before a run (`src/app/icon-names.ts`), so an icon made again reaches a browser that kept the old one; the favicon alone keeps its name, at the page's root, where it is published to be read again within a minute (the review of PR-348). A frame under `art/frames` is trimmed to the box its pixels fill and copied under a name that carries the trimmed picture's hash, and its name and slice go into `packages/client/generated/frames.css`, a stylesheet the page is built with (`docs/process/assets.md`, rule 41; Issue-385). A hero's portrait is cut from its set's still facing south and published the same way as an icon, with `art/portraits/pictures.json` naming each by its set, which the page reads with the icons' index (`src/app/icon-names.ts`; `docs/process/assets.md`, rule 42).

The favicon is one of that art, `art/icons/favicon.png`, so the client has no `public` folder; the build also puts it at the site root as `/favicon.png`, which `scripts/publish-client.sh` publishes with the page's short cache rather than the year-long one of everything else, because browsers ask for a favicon at a fixed address (Issue-89).

## Held back

Nothing (Issue-156).

## Why

The shape rules are Angular's own current recommendations, standalone components, zoneless change detection, signals, `inject()`, `@Service()`, the v20 style guide's names, and the `all` tier of angular-eslint is their enforcement. A developer who knows Angular should recognize the client at a glance, so accepted practice is weighted over the code as it was (Issue-145).

Where the data lives follows from decisions 0024 and 0030: the token, the version header and the `outdated` flag are handled in one place or they are handled inconsistently, and a component that called the hub would carry a copy of that handling. The generated client is decision 0012's shape (Issue-156): the operations are validated against the committed schema by lint and by generation, so a fragment spread on a union with no such member fails before it is pushed, not at the stack URL (PR-192); fragment masking is off because one service reads every result; the views derive from the generated types so that a change of the schema is a change of the client's types in the same diff; and the pending state is per control, never a page-wide flag that disables unrelated controls, because a mutation's in-flight state is per call in Apollo as in Angular's own guidance. The refusal-to-words table beside the component keeps the hub's refusal types as the contract names them and the words where a reader of the panel expects them (Issue-82, Issue-115; the types since Issue-155). A wire value passing through rather than throwing is the client's half of decision 0030: a tab older than the hub is normal between a deploy and the reload the `outdated` flag triggers (the review of PR-192). A table typed by its closed set makes a missing word a compile error rather than a silent fallback to the wire's spelling, and a static file is checked at its fetch because the art's JSON is not the hub's and a cast checks nothing (Issue-268).

The scene boundary is decision 0028's reason: the rules never run in PixiJS, so they are tested without a renderer, and PixiJS is loaded only where it is drawn, so the first page stays small. The plain modules exist for the same reason at a smaller scale: an argument over layout arithmetic is settled by numbers in a function with a spec (Issues 89, 95 and 99).

The template rules are Issue-149's readability convention made general: a literal in a template has no name and no reason beside it, a named constant has both. The lint rules that are off are off for a convention, not for the code: signals are read by calling them, the game has one language, and the complexity a template could hide is already forbidden by rule 9.

The test rule is decision 0044: Angular's own harness was current practice, and Testing Library was chosen for its vocabulary, which reads the same in any framework, and because a spec that asks for a role and a name fails when a control has neither, as a CSS selector does not. The zoneless entry point keeps the specs clear of deprecated modules; it also forces no change detection after an event, so a spec passes only if the signals bring the page up to date, as they must in the browser.

The styles rule is decision 0037, plain CSS with a token layer, with its colour in two layers by decision 0061: custom properties are the token mechanism in both camps, Angular defaults to CSS and recommends nothing, and Angular Material, the one place Sass would be required, emits its theme as custom properties that plain CSS reads. The arithmetic reads the tokens because pixel constants that copy them are true only at the default font size (the review of PR-189).

Angular releases its packages as one set and names the TypeScript versions it accepts, so its packages are pinned to one version and moved as one (Issue-45).
